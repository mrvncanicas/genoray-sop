PapayaOP + Triana on Windows 11

Installation guide for Windows 11 24H2 — SQL Server compatibility fix

Root Cause

  • PowerShell 2 is fully removed in Windows 11 24H2
  • Bundled SQL Server 2012 (inside the Genoray installer) requires PS2
  • Installer fails silently at the SQL install step

✓ Fix: Install SQL Server 2019 Express manually before running the Genoray installer

1

Install .NET Framework 3.5

Required prerequisite for SQL Server 2019

▾

Open PowerShell as Administrator (Win + X → A) and run:

⚡ PowerShell (Admin)
Enable-WindowsOptionalFeature -Online -FeatureName "NetFx3" -All

Allow it to download and install. Restart if prompted before continuing.

2

Install SQL Server 2019 Express

Manual install with correct instance name and auth settings

▾

Download SQL Server 2019 Express from Microsoft:

🌐 Download URL
https://www.microsoft.com/en-us/download/details.aspx?id=101064

Run the installer and choose Custom. Set these values during the wizard:

  • Features: Database Engine Services only — uncheck everything else
  • Instance name: GENORAY
  • Instance ID: leave as default (SQLEXPRESS)
  • SQL Browser: set to Automatic
  • Authentication: Mixed Mode (SQL Server and Windows)
  • SA password: triana
3

Enable TCP/IP and Set Fixed Port

Configure SQL Server to accept connections on port 1433

▾

Open SQL Server Configuration Manager:

📂 Run
C:\Windows\SysWOW64\mmc.exe /32 C:\Windows\SysWOW64\SQLServerManager15.msc

In the Configuration Manager window:

  1. Go to SQL Server Network Configuration → Protocols for GENORAY
  2. Right-click TCP/IP → Enable
  3. Right-click Named Pipes → Enable
  4. Right-click TCP/IP → Properties → IP Addresses tab
  5. Find IP9 (127.0.0.1): set Enabled = Yes, TCP Port = 1433, TCP Dynamic Ports = blank
  6. Find IPAll: set TCP Port = 1433, TCP Dynamic Ports = blank
  7. Click OK → Go to SQL Server Services → Restart SQL Server (GENORAY)
4

Configure Registry for 32-bit Compatibility

Old InstallShield installers check the WOW6432Node path

▾
Old 32-bit Genoray installers check a different registry path than 64-bit apps. This step ensures they find the SQL instance.
⚡ PowerShell (Admin)
# Mirror instance to 32-bit registry
New-Item -Path "HKLM:\SOFTWARE\WOW6432Node\Microsoft\Microsoft SQL Server\Instance Names\SQL" -Force
Set-ItemProperty -Path "HKLM:\SOFTWARE\WOW6432Node\Microsoft\Microsoft SQL Server\Instance Names\SQL" -Name "GENORAY" -Value "MSSQL15.GENORAY"

# Disable forced encryption for legacy ODBC clients
New-Item -Path "HKLM:\SOFTWARE\WOW6432Node\Microsoft\Microsoft SQL Server\MSSQL15.GENORAY\MSSQLServer\SuperSocketNetLib" -Force
Set-ItemProperty -Path "HKLM:\SOFTWARE\WOW6432Node\Microsoft\Microsoft SQL Server\MSSQL15.GENORAY\MSSQLServer\SuperSocketNetLib" -Name "ForceEncryption" -Value 0
Set-ItemProperty -Path "HKLM:\SOFTWARE\WOW6432Node\Microsoft\Microsoft SQL Server\MSSQL15.GENORAY\MSSQLServer\SuperSocketNetLib" -Name "ForceStrict" -Value 0

# Start SQL Browser and set to Automatic
Set-Service "SQLBrowser" -StartupType Automatic
Start-Service "SQLBrowser"
Restart-Service "MSSQL`$GENORAY" -Force
5

Create Database and Tables

Create db_triana and run the schema scripts

▾
sqlcmd cannot handle spaces in file paths with the -i flag. Copy the scripts to C:\temp first.
⚡ PowerShell (Admin)
# Create temp folder
New-Item -ItemType Directory -Path C:\temp -Force

# Create the database
sqlcmd -S ".\GENORAY" -E -C -Q "CREATE DATABASE db_triana"

# Copy scripts to C:\temp
Copy-Item "D:\PARAMETERS\Software from DVD\PAPAYA3D OP\20181107_P3D_1.0.13.0\mssql\SQLQuery_CreateOrderTable.sql" "C:\temp\CreateOrderTable.sql"
Copy-Item "D:\PARAMETERS\Software from DVD\TRIANA\Triana_2.5.10.0\Triana_2.5.10.0\mssql\triana_update_tables.sql" "C:\temp\triana_update_tables.sql"

# Run the scripts
sqlcmd -S ".\GENORAY" -E -C -i "C:\temp\CreateOrderTable.sql"
sqlcmd -S ".\GENORAY" -E -C -i "C:\temp\triana_update_tables.sql"

Cap SQL Server RAM Usage

Prevent SQL from consuming all available memory

▾

SQL Server defaults to unlimited memory. Cap it at 1GB — more than enough for Triana:

⚡ PowerShell (Admin)
sqlcmd -S ".\GENORAY" -E -C -Q "EXEC sp_configure 'show advanced options', 1; RECONFIGURE; EXEC sp_configure 'max server memory', 1024; RECONFIGURE;"

Install PapayaOP

Run installer — uncheck SQL install option

Critical Step ▾

Run setup from the installer folder:

📂 Path
D:\PARAMETERS\Software from DVD\PAPAYA3D OP\20181107_P3D_1.0.13.0\setup.exe
When the Setup Type screen appears — UNCHECK "Install MS-SQL DB". This skips the broken bundled SQL Server 2012 installer. The rest of the wizard completes normally.

Install Triana

Dismiss PS2 warnings — install still completes

▾

Run setup from the installer folder:

📂 Path
D:\PARAMETERS\Software from DVD\TRIANA\Triana_2.5.10.0\Triana_2.5.10.0\setup.exe
  • Select Server
  • Select Microsoft SQL Server Database
  • Dismiss all PowerShell 2 warnings — click Cancel on each
  • Click OK on the SQL install failure dialog
  • Triana will complete installation successfully despite the warnings
9

Configure Triana Database Connection

Set connection string in ConST config window

Critical Step ▾

Launch Triana — the ConST configuration window opens automatically:

  1. Click "Encryption not supported on the client" button
  2. Set Server Name to 127.0.0.1,1433
  3. UID: sa
  4. Password: triana
  5. Click Test → confirm "Connection successful"
  6. Click Update → OK
Note: Use 127.0.0.1,1433 (comma, not backslash) — this connects directly to port 1433 and bypasses the SQL Browser name resolution issue with Triana's legacy ODBC driver.

Restore Patient Database

Only if migrating from an existing install

If Applicable ▾

If patient data exists from a previous install, restore from the most recent .bak file in D:\PARAMETERS\SQL\:

⚡ PowerShell (Admin)
sqlcmd -S ".\GENORAY" -E -C -Q "RESTORE DATABASE db_triana FROM DISK='D:\PARAMETERS\SQL\triana_db_YYYYMMDD-HHMMSS.bak' WITH REPLACE, RECOVERY, MOVE 'db_triana' TO 'C:\Program Files\Microsoft SQL Server\MSSQL15.GENORAY\MSSQL\DATA\db_triana.mdf', MOVE 'db_triana_log' TO 'C:\Program Files\Microsoft SQL Server\MSSQL15.GENORAY\MSSQL\DATA\db_triana_log.ldf';"

Replace YYYYMMDD-HHMMSS with the actual filename of the backup.

RAMDisk Fix (Dataram)

Only if unit uses a Z: drive for image processing

If Applicable ▾

If RAMDisk fails with "Failed to allocate requested disk memory (AWE)":

  1. Win + R → type secpol.msc → Enter
  2. Navigate to Local Policies → User Rights Assignment
  3. Double-click "Lock pages in memory"
  4. Click Add User or Group → type Administrator → OK
  5. Restart the machine — policy only takes effect after restart
  6. After restart, launch Dataram RAMDisk as Administrator → Start RAMDisk
